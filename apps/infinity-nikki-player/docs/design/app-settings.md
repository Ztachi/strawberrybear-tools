# 应用设置、关闭行为与播放倍速

## 界面与设置归属

主窗口右上角提供一个设置入口，`SettingsDialog` 使用已有 antdv-next Modal 和表单，并复用 MIDI 编辑器帮助的 `SectionDocument`。左侧目录按常规、联系我们、关于排列，窄窗口也保持左右布局；右侧连续展示所有内容并统一滚动，目录负责定位和同步高亮。语言和关闭选项复用设置 Store，修改即保存；关于部分嵌入已有更新状态和更新日志入口，系统“关于”菜单直接定位该章节。播放偏好留在播放器，更新操作集中在关于中。

设置目录不重复展示标题，目录和正文标题分别使用偏好调节、联系沟通、应用信息图标。Modal 使用 `destroyOnHidden`，关闭后销毁正文和滚动位置，重新从设置入口打开即从顶部开始。托盘说明仅在“关闭时询问”右侧的提示图标中展示，支持悬停或键盘聚焦。联系我们用两条紧凑信息行展示平台和可复制账号，名称与账号统一行高，通过 Typography 的语义样式使账号及复制按钮垂直居中；官网入口位于标题右侧，不再增加内层卡片或重复网址。关于依次展示 Logo、版本、更新操作，不重复产品描述。更新、更新日志、导出诊断使用一致的小尺寸按钮，图标均在左侧。所有章节跟随内容自然高度；短末节到达滚动边界时，SectionDocument 通过 Anchor 的 `getCurrentAnchor` 扩展保留目录定位和高亮，不增加空白占位。两种关于呈现共用内容与操作逻辑。

关闭选项保存为 `close_action: tray | quit` 与 `close_action_confirmed: boolean`。旧配置默认托盘且尚未确认；首次关闭提供单选、记住选项和取消。未记住会继续询问；在设置中主动选择关闭行为视为确认，也可重新启用关闭询问。保存关闭选项失败时恢复内存值并保留窗口。

播放倍速组件受控，仅发送速度变更。`MusicPlayerCore` 将它放在音量控件后，调用已有 `playerStore.setSpeed()`，沿用预览时钟与原生速度入口。变速时立即发布音频的最新音乐位置，悬浮层从该位置重建按键执行器并释放旧按键，避免游戏演奏与声音速度不同。Slider 范围 0.5–3、步进 0.1，每隔 0.5 提供可点击的数字刻度；按钮显示一位小数和 `x`，浮层内部不重复单位或标题，保留恢复原速图标。浮层仅保留一层小间距，隐藏滑杆的额外 Tooltip，在收起的 360×156 悬浮窗口内完整显示。

悬浮模式的倍速文字采用既有反白控件变量。恢复原速使用无内边距的 16px 图标按钮，保留可访问名称和键盘焦点。

当前 antdv-next Popover 是 WebView 内的 DOM 弹层，Teleport 或 z-index 无法让它绘制到原生窗口外；这不代表操作系统的弹出控件有同样限制。macOS 的 NSPopover、Windows 的原生弹出菜单可由系统承载。若后续要让滑杆等网页控件越过小悬浮窗口，应优先评估 Tauri 原生弹出窗口，复用内容并处理宿主关系、屏幕坐标、缩放和失焦关闭；本次仅分析该方案，倍速控件仍通过紧凑布局适配原有窗口尺寸。

## 悬浮列表浏览

`OverlayPlaylistPanel` 独立管理搜索词和浏览歌单，顶部 24px 搜索框与可搜索 Select 固定，歌曲列表单独滚动；展开窗口仍为 360×320。Select 先列全部歌曲，再列用户歌单。搜索忽略大小写和首尾空格，即时筛选展示名称，不修改曲库或播放队列。

切换歌单只更新浏览条件；点击歌曲才把所选集合的完整有序列表与来源一起交给 OverlayView，沿用三秒倒数。上一曲、下一曲仍遍历完整播放队列。收起保留浏览条件并关闭 Select 弹层；浏览中的歌单被删除时回到全部歌曲。“定位”清除搜索，必要时恢复播放来源或全部歌曲，再滚动到当前歌曲，不启动播放或变更播放域。定位按钮保持透明底色；歌曲行沿用原有宽度和左右间距。

## 关闭与退出的分离

`app_lifecycle` 用 Tauri 自带 `tray-icon` 能力提供托盘，不增加托盘依赖库。主窗口 CloseRequested 始终先阻止原生销毁，再发 `main-window-close-requested`；前端 `AppCloseHost` 调用独立关闭控制器选择隐藏或退出。系统退出请求、托盘退出和 Windows 应用退出菜单发 `app-quit-requested`，绕过关闭方式选择，仍执行编辑保护。快速重复请求共享同一次处理。

隐藏前先读取各相关窗口的可见性，避免查询失败留下半完成隐藏。保存可见窗口标签，隐藏失败回滚；恢复只展示这些窗口并聚焦主窗口，保持原先隐藏的编辑窗口不变。恢复失败保留标签供再次尝试；macOS Dock 重新打开也走同一恢复函数。

MIDI 编辑页面注册退出保护，页面在 KeepAlive 缓存中仍参与确认。其他当前页面复用主窗口持有的离开保护，包括未保存的模板编辑。未保存项目使用已有保存、放弃、取消流程；草稿刷新或停止播放失败阻止退出。打开录制工作区时暂停并保存检查点，提示用户先应用或放弃录制；独立编辑窗口会被聚焦。主窗口实际 destroyed 才清理子窗口，关闭请求或托盘隐藏不销毁编辑会话。

从托盘或系统菜单请求退出时，先恢复窗口再通知前端；如果仍在迷你悬浮模式，复用退出悬浮流程恢复正常窗口尺寸，再显示编辑确认。只有所有保护通过且停止播放成功后才调用 `quit_application`。原生 `app.exit(0)` 带显式退出码，避免再次触发系统退出保护。

## 原生标题区域

独立 MIDI 编辑器中的键盘录制入口排在编辑工具栏后。录制组件接收宿主是否包含原生标题区域，独立窗口在 macOS 使用 `--window-title-safe-inset`，与 `WindowTitleBar` 共用 90px 留白；主内容区内的录制工作区不额外留白，Windows 使用自身窗口按钮布局。

## 验证

- 单元测试：首次关闭、记住/不记住、取消、重复关闭、退出否决和保存失败；独立窗口只在父窗口 destroyed 后清理。
- Rust 持久化测试：旧配置默认值与新关闭选项往返。
- Playwright `app-settings.spec.ts`：独立窗口按钮顺序与标题留白、连续设置正文、目录图标与定位、说明 Tooltip、关闭销毁与重新打开位置、内嵌关于布局、系统关于入口、语言持久化、窄窗口、首次关闭和编辑退出保护；倍速范围、步进、数字刻度、恢复原速按钮尺寸，以及 360×156 悬浮视口的反白文字与浮层边界。
- Playwright `overlay-playlist.spec.ts`：即时显示筛选、完整播放队列、歌单可搜索选择、紧凑控件、收起保留条件、定位和删除浏览歌单。
- `cargo run --example app_lifecycle_smoke`：隔离空白原生窗口验证关闭拦截、隐藏、恢复、保留子窗口及不展示原先隐藏的窗口；不读取用户设置或启动演奏。

Windows 托盘与任务栏、macOS 托盘与 Dock 的最终设备验收须在对应平台执行。
