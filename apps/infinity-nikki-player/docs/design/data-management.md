# 数据管理、备份与云同步

## 所有者与数据边界

原生 `data_management` 统一解析资料目录、构建快照、管理本地备份、准备恢复和执行迁移；`cloud_sync` 管理云配置、系统凭据、传输及自动上传。前端只编排表单、摘要确认与编辑准备，不自行打包文件或操作云端密钥。

云快照包含 `midi_library`（含 `.midi-config`）、`song_lists`、`song_list_covers`、`templates`（含初始化标记）、已保存 `midi_projects`。保持标识、文件名引用、顺序、时间与项目内容。本地快照另外包含文件草稿，以及前端按白名单收集的模板草稿。

设备签名身份、同步凭据、FPS、键盘模拟、关闭偏好、窗口位置、更新记录、日志和缓存不属于作品快照。在线曲库 IndexedDB 的 `identity` 存储不清理、不导出。模板草稿只允许新建、旧版新建键和按名称编码的编辑键；界面重置使用确切偏好键，不能调用 `localStorage.clear()`。

## 快照与本地备份

ZIP 由格式清单、用户资料和本地模板草稿组成；清单包含格式版本、应用版本、创建时间、来源设备和内容数量。云端额外校验归档大小与 SHA-256。读取时检查格式、目录白名单、重复条目、软链接、解压总量、JSON 结构和数量，恢复保留原 ID，不使用会重新生成 ID 的分享导入命令。

资料写入和快照收集共享原生协调器。锁内只收集不可变内容，压缩与网络传输在锁外执行；同锁记录变更代数，上传期间的新保存继续进入下一次任务。草稿、缓存和本机设置不触发云上传，读命令补写资料元数据时也记录变更。

自动备份默认每 24 小时、保留最近 10 份；间隔支持关闭、6/12/24/48 小时、7 天，份数支持 3/5/10/15/20/30/50。数量上限适用于所有本地备份，包含手动和恢复前备份。新备份成功落盘后才清理历史。主窗口响应原生调度事件，收集已落盘模板草稿；调度失败有冷却，不不断弹窗或重复写盘。

## 恢复与目录迁移

恢复先下载或读取文件并在资料目录暂存、校验，展示摘要后再请求编辑器保存或取消。未应用的录制阻止恢复；保存失败不继续。前端停止试听和演奏，原生取消并等待活动云任务结束，创建恢复前备份，再通过带持久事务记录的目录替换提交。提交成功后保持原生写冻结直到重启，防止独立窗口、页面缓存或旧草稿回写。

本地恢复应用备份中的草稿；云恢复将原草稿收入恢复前备份并清空活动草稿。模板草稿恢复通过系统配置目录中的待应用记录传递，主入口在挂载任何编辑器前回填 localStorage，成功后才确认记录。启动时先恢复或回滚上次中断的原生事务，再进行资料读取和种子初始化。

资料目录指针放在固定 `app_config_dir`。迁移只处理资料、文件草稿和本地备份；系统配置、凭据、日志、缓存及 WebView 存储保持平台原位置。新旧目录不得互相包含；普通目标不能覆盖已有资料，恢复默认目录须明确确认，并将旧资料快照与旧备份历史合并到迁入后的备份列表；同名备份内容不一致时拒绝覆盖。本次合并不清理历史，后续创建备份时再按保留数量处理。迁移采用暂存复制和事务提交，保留源目录，完成后重启。已配置的资料目录丢失或不可访问时提示原路径并停止初始化，不创建空库。

## 云同步与凭据

两种服务使用相同配置和状态接口，同一时间只启用一种。服务及自动上传默认关闭，远端根目录默认 `infinity-nikki-player-sync`，配置名默认 `default`。WebDAV 通过既有 reqwest 逐层创建目录并读写；S3 使用 object_store 的签名与兼容存储实现。

保存配置后由前端测试连接，测试失败保留已保存事实；测试使用独立临时对象并清理。上传、下载使用已保存配置，手动操作先展示远端摘要。自动上传采用 1 秒防抖、最长等待 10 秒，只上传本地后续保存，不自动下载或合并其他设备的数据。

云服务原生状态包含阶段、待上传状态、最近成功时间和错误。任务互斥，取消会等待任务退出；配置代数隔离迟到结果。完整归档先上传，最后发布清单；保留当前和上一份已发布归档，读取遇到轮转或校验变化时重新获取清单，失败不修改本地资料。

云配置独立保存，密码和 S3 私钥通过 keyring 存入 macOS Keychain／Windows Credential Manager。前端只能读取已配置标志，提交时明确保留、替换或清除。先创建新凭据再提交配置引用，失败保留旧引用；不能退回明文存储。日志不可记录凭据或包含凭据的网络错误详情。

## 验证

原生隔离测试覆盖格式往返、白名单、损坏归档、恢复和迁移回滚、启动恢复、写锁和代数；云测试使用本地服务验证真实 WebDAV 与 S3 适配器、错误、取消、轮转和凭据失败。浏览器使用隔离 IPC 端口验证界面，不访问用户目录或真实云账号。

自动化测试不能代替 Windows／macOS 安装副本上的自启动、托盘和系统凭据验收，也不能替代用户服务商的端到端验证。最终验收应使用隔离资料目录及测试云目录。

在应用目录执行 `pnpm type-check`、`pnpm lint`、`pnpm test`、`pnpm test:browser` 和 `pnpm build`。原生执行 `cargo test --locked --manifest-path src-tauri/Cargo.toml --lib`，CI 在 macOS 与 Windows 复用全部原生测试。
