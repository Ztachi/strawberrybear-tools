# 用户更新日志与发版要求

## 内容 owner

应用内日志面向实际使用者，按版本突出功能、操作方式和可感知的问题修复，不复制提交记录。
GitHub 的 `CHANGELOG.md` 和 Changeset 保留技术细节，继续按原发布流程生成。两者不可相互替代。

- `src/const/release-notes.json`：版本、日期、稳定 id，从最新到最旧排列。前端和 Rust 共用这份目录。
- `src/i18n/locales/release-notes/zh-CN.json`、`en-US.json`：每版的 `title` 和 `highlights`，经现有 vue-i18n 加载。
- 历史日期来自 GitHub Release 的实际 `published_at`，统一为 UTC+8 的 `YYYY-MM-DD`，不用提交或 tag 创建日期。
- 只收录本播放器实际发布的版本，不为跳过的版本号补空记录，不把公共依赖版本列成应用版本。

## 每次发版必须同步维护

1. 整理这次版本的用户重心，与中文 Changeset 一起准备；版本 PR 确定应用版本后，在目录加入该版本和计划发布日期。
2. 同时提供中英文标题和正文。通常保留 3–6 个重心，小补丁可只有一项。标题描述本次变化，正文说明用户能做什么、哪种操作变顺畅；必要时指出入口或用法。
3. 不写提交哈希、包名、内部类名、构建过程或与用户无关的 CI 修复。不添加“删除仍可撤销”等无用解释；快捷键沿用 `Option/Alt`、`Ctrl/Cmd`。
4. 未发布功能不能补进旧版本记录。历史内容可纠错，但 id、版本与发布日期不能随意修改。若发布跨日，发布前更新计划日期为实际发布日。
5. 执行 `node scripts/check-release-notes.mjs`、`node --test scripts/check-release-notes.test.mjs`，再执行应用类型检查、lint、test 和 build。人工复核正文是否真正概括这次改动。
6. 发布前确认版本、日期、中英文内容和 GitHub 技术日志一致，再走现有发布流程。

构建和发布 `prepare` 都调用同一个日志校验器：缺少当前版本、语言内容为空、重复版本或 id、SemVer 排序错误、非法日历日均直接失败。这个校验只能防止遗漏和结构错误，不能代替用户文案审阅。

## 首次提示与迁移

日志随安装包离线提供，不依赖网络请求、GitHub API 或更新下载线路。版本来自实际运行包信息，比较复用 Rust `semver`；前端只展示原生层返回的版本列表。

主窗口首屏准备完成后执行一次启动处理。自动弹窗包含 `(最高已读版本, 当前运行版本]` 的所有已发布日志，最新在前。关闭、取消或阅读后，本次运行均不会再自动弹出；“关于”版本右侧的“更新日志”始终展示完整历史，且只包含不高于实际运行版本的内容，不提供再次打开本次升级区间的入口。

`release-notes.json` 由 Tauri Store 单独持久化 `highestSeenVersion`，不复用普通设置，也不使用前端滚动/页面缓存。进入首屏后显式保存，不能依赖退出时自动落盘。主窗口拥有自动提示，音轨独立窗口不会重复执行。

| 场景                               | 行为                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| 首次安装，没有旧设置和有效安装记录 | 不弹窗，记录当前版本作为基线；完整日志仍可从关于打开                                   |
| 已有记录，跨多个版本升级           | 展示已读版本之后至当前的全部日志，跳过未发布版本                                       |
| 从尚无此功能的旧版自动更新         | 有目标与当前版本一致、已确认成功的安装记录时，使用其中的来源版本计算范围               |
| 旧版手动覆盖安装，无法确认来源版本 | 有旧设置时只提示当前版本，不猜测用户以前使用的版本                                     |
| 旧安装记录残留、安装未生效         | 不用该记录推断升级区间；已有已读记录优先                                               |
| 相同版本重开或刷新                 | 不再自动提示                                                                           |
| 降级、打开旧副本，再回到已读新版   | 保留最高已读版本，不降低基线、不重复提示                                               |
| 已读字段缺失或损坏                 | 按未知旧版/首次安装处理，建立当前基线                                                  |
| 读取或写盘故障                     | 不阻挡首屏和演奏，完整历史仍可离线打开；记录具体错误供诊断，未成功落盘时下次启动可重试 |
| 开发构建                           | 完整历史可手动查看，不自动提示、不修改正式安装的已读记录                               |

没有旧设置、已读记录或可靠安装记录时，无法区分首次安装和用户主动清空数据后的安装，统一按首次安装处理。

## 共用目录与界面

`components/SectionDocument.vue` 提供目录与正文滚动容器。MIDI 编辑帮助与日志共用它。目录使用 antdv-next `Anchor` 的定位与滚动同步能力，阻止写入 hash，不影响主窗口前进/后退历史；正文滚动使 active 项变化时，目录只在该项超出可见范围时平滑滚动，让当前项完整可见，不连带滚动正文或外层弹窗。内容通过默认 slot，目录项通过 `item` slot 扩展。

日志目录显示版本和日期，右侧正文独有时间树连线。圆点、轨道与状态色读取主题变量，最新版本使用小实心点与三圈连续扩散的涟漪：每圈缓慢扩散四秒半，间隔一秒半发出，均分周期、无缝衔接，不移动正文；开启减少动态效果时使用单个静态圆环，目录直接定位。正文允许选择复制，窄窗口下目录和正文各自滚动、自然换行。“关于”的版本与检测更新入口始终居中，右侧小字号链接打开完整日志。

## 验收

- 原生范围测试：首次安装、首次迁移、跨版本更新、重复启动、无效及过期安装记录、降级和 `1.10.0` 的 SemVer 顺序。
- 控制器测试：并发启动去重、完整历史入口和迟到的启动任务不覆盖用户选择。
- 浏览器：自动范围与完整历史、再次启动不重复、目录定位不修改路由、正文可复制、中英文、窄窗口与减少动态效果。
- 发版校验器：真实历史内容及漏写当前版、缺译、空内容、错误排序、重复 id、非法日期。
