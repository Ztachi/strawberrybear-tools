# 更新故障排查

## 更新后仍显示旧版本

先打开“关于”核对实际版本。若提示“上次更新尚未生效”，表示本次启动的版本尚未达到上次目标，不能据此认定下载包有问题。

1. 关闭其他播放器副本。检查启动的是原安装目录、下载目录、桌面旧快捷方式，还是另一份复制的应用。
2. 在关于页重试更新；下载完成但取消保存确认时，点击“安装并重启”即可继续，不必重新下载。
3. 如果仍然无效，使用关于页手动下载。Windows 选择原安装目录，保持与原安装一致的用户身份；macOS 解压应用后替换原应用，通常位于“应用程序”。不要从只读镜像、压缩包或旧副本启动。
4. 导出诊断，连同关于页版本、操作系统、普通/管理员启动方式、安装位置和具体失败步骤交给维护者。诊断中包含当前与上次运行路径，可帮助辨别多副本问题。

## 检查失败或下载失败

“检查失败”表示本次无法获得有效版本信息，不表示已经是最新版本。恢复网络后可点击检查；应用也会按节流规则补查。

下载自动先尝试加速线路，再尝试 GitHub。全部失败后停止，用户可以取消、重试或手动下载。签名校验失败时不会安装，切勿通过关闭签名校验解决。代理是公共服务，遇到限流、阻断、缓存和上游故障时，两条线路可能同时不可用。

有候选版本时，两种手动下载入口指向同一版本的安装资产。macOS 下载的是签名更新压缩包，解压后得到 `.app`；Windows 下载 NSIS `.exe`。尚未获得候选清单时，使用官网或已知版本发布页继续手动安装。

## 保存取消与安装失败

保存、丢弃、取消沿用编辑器原有确认。取消或保存失败会保留下载包，不退出应用；修正编辑内容后再次安装即可。不能保存安装记录或停止演奏时同样不会交给安装器。

安装失败后优先确认磁盘空间、安装目录权限、运行副本和用户身份。macOS 在只读位置无法原地替换时，改为手动安装到可写目录。Windows 保留官方安装器目录恢复行为，避免在不同用户间切换安装身份。

## 旧版本迁移

`0.2.0–0.2.1` 的更新按钮存在前端更新对象调用缺陷，新版清单不能远程修复旧客户端代码，请手动下载安装新版。`1.1.2` 仅使用 GitHub 检查，受限网络下也可能需要手动安装；`1.1.3` 已有加速入口，但没有本次完整的下载切源和重启确认机制。

覆盖安装前可以备份用户数据目录；保留应用标识及现有设置、模板、歌单、草稿文件，不要卸载时清除用户数据。覆盖完成后核对实际版本与原有数据，再移除多余旧副本。

## 本地诊断

日志由 Tauri 官方日志插件写入系统应用日志目录，单文件约 1 MiB，最多保留 3 份轮转文件及当前日志。关于页“导出诊断”会让用户选择保存位置，打包更新状态和日志；取消选择不产生文件。

应用不会自动上传诊断。日志可能包含本机路径和操作信息，分享前可检查内容。应用数据和日志的实际系统路径可以通过诊断中的运行路径、Tauri 路径 API 与安装用户定位。
