# 架构与开发约定

## 职责

- Vue：主页、游戏 HUD、设置、教学、暂停、历史与劳动报告。
- Pinia：页面需要响应显示的对局摘要；逐帧物理状态不进入响应式状态。
- `src/game/engine`：Rapier2D 固定步长模拟、PixiJS 绘制、输入和碰撞事件。
- `src/game/systems`：材料、验收、事件选择与称号等纯业务规则。
- `src/db`：Dexie 存档、设置与历史记录事务。
- `src/config/balance.ts`：唯一数值平衡文件；物理、经济、事件、规则和称号参数集中维护。
- `src/config/board.ts`：只维护台面几何，不混入平衡数值。

## 坐标与素材替换

台面采用 720×1280 设计坐标，Rapier 世界按 20 像素/米换算。Pixi 根容器整体等比缩放，因此不同设备不会改变碰撞结果。

当前 `GameEngine` 以 `src/assets/board-playfield.png` 作为 720×1280 主题底板，用 `Graphics` 绘制与碰撞体严格对齐的轨道、机关、拍板、目标和反馈状态。替换角色或机关动画时保留刚体和碰撞体创建逻辑，仅将对应 `Graphics` 换为 `Sprite`/Spine，并让锚点和设计坐标保持一致。

## 存档一致性

每次验收先在内存固定评级、倍率、材料快照和收入，随后立即写入当前对局。完成对局时通过 Dexie 事务将固定结果写入历史、更新累计统计并删除未结束存档，历史数据不随新配置重算。

完整对局和设置在读写边界经过 Zod 校验。写入前必须将 Vue Proxy 转为可结构化克隆的纯数据；增加字段时同步维护 Schema、默认值、旧版本迁移和数据库测试。

所有可暂停流程保存“剩余时长”，包括随机事件、事件冷却、验收捕获、验收冷却、陨星捕获和结束动画。`Date.now()` 只记录开始、结束和存档时间，不能用绝对结束时间驱动可暂停状态。

## 引擎与页面契约

`GameEngine` 管理 Rapier 刚体、Pixi 显示对象、固定步长、输入和碰撞；Pinia 通过离散事件接收机关、目标、传感器、发射状态和物理快照。页面不读取逐帧刚体状态。

发射状态为 `ready → traveling → entered`。只有收到 `entered` 后才开始本局计时；力度不足回落时回到 `ready`。这个离散契约同时供 UI 和 E2E 使用，避免根据动画时长猜测物理结果。

引擎创建的 window 监听、指针监听、ResizeObserver、动画帧和 Pixi 实例必须在 `destroy()` 中成对清理。

## 国际化与设置

所有用户可见文字通过 `vue-i18n` 输出，当前支持 `zh-CN` 和 `en-US`。Pixi 内文字由 GameEngine 登记 i18n key，运行中切换语言时原位刷新，不需要重建物理世界。音量、静音、语言和键位共用同一个设置 store，并持久化到 Dexie。

第一版核心音效由 `src/game/engine/audio.ts` 在本地生成短 WAV，并通过 `@pixi/sound` 播放，因此离线可用且服从统一音量/静音。正式音频可以保留稳定别名和触发点，直接替换音源。
