# 国际化规范

## 适用范围

本文是仓库级通用 i18n 规范，覆盖所有用户可见的 UI 文本（Web、桌面、移动端、小程序）。具体 i18n 库、资源目录、加载方式由各应用 `docs/` 声明并维护。

## 规则

1. 所有项目必须做国际化，初始只适配中英文（zh-CN / en-US）。
2. 所有用户可见的文本必须使用国际化 key；不允许在源码中硬编码用户可见文本。
3. 默认语言为中文（zh-CN），英文（en-US）作为可选适配。
4. 使用成熟的 i18n 库（如 vue-i18n、react-i18next、Tauri 内置 i18n 等），按应用技术栈和构建工具选择。
5. 应用必须在 `apps/<app>/docs/` 声明：i18n 库名、资源目录、加载策略、回退语言和新增语言的流程。

## 翻译 Key 命名规范

使用点号分隔的层级结构，命名从「通用」到「页面」再到「具体字段」：

```txt
common.button.confirm       # 通用 - 按钮 - 确认
common.button.cancel        # 通用 - 按钮 - 取消
page.home.title             # 页面 - 首页 - 标题
page.user.profile.name      # 页面 - 用户 - 个人资料 - 姓名
```

补充：

- 同一概念在不同地方必须使用同一个 key；不要因为翻译措辞不同就拆出新 key。
- 面向持久化或接口对齐的 i18n key，建议同时提供稳定的机器字段（例如 `id` / `code`）和展示字段，避免语言切换后历史数据错位。
- 新增页面或模块时，优先在该页面对应命名空间下加 key（如 `page.<name>.<field>`），避免在根命名空间堆砌。

## 应用专属 i18n

- 资源目录（如 `src/i18n/`、`locales/`、Tauri `i18n/` 等）由各 app `docs/` 维护。
- 加载策略（静态导入 / 动态 lazy load / 后端下发）由 app 决定。
- 跨页面 / 跨 app 复用的文案，沉淀为通用 key；只在单个页面使用的文案，保留在对应页面的命名空间。
