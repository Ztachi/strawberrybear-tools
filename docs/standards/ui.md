# UI 通用规范

## 适用范围

本文是 UI 类规范的通用层，覆盖所有有用户界面的应用（Web、桌面、移动端、小程序等）。具体技术栈的细节（Vue / React / Svelte / 原生 / 小程序）由各应用 `docs/` 维护；本文**不规定**框架特定语法、模板语法、状态库选型。

## 原则

- 优先使用各应用选定的组件库及其生态，不重复实现基础按钮、弹窗、表格、表单、抽屉、提示等通用组件。
- 页面、screen、view 保持信息结构清晰；移动端必须检查长文案换行、截断、点击区域和安全区。
- 样式优先使用应用内主题 token 或 CSS 变量，不在业务组件里硬编码颜色、字号、间距。
- 业务视图单元留在 app 的 feature、路由入口局部视图单元或 app 公共视图目录中；只有明确跨应用复用需求时才进入公共包。
- 不把 app UI 规则写入 `packages/*`。
- 能用 CSS 表达的布局、尺寸、滚动和响应式约束，不用 JS 测量 DOM 后再回写状态。优先使用 `flex`、`grid`、`min-height`、`max-height`、`calc()`、`clamp()`、CSS 变量和原生 `overflow`。
- 可增长的同构 UI 使用数组或对象列表驱动渲染，不复制多段只改文案、图标或颜色的模板。

## 组件化和样式复用

- UI 开发默认追求模块化、组件化、高复用和解耦。一个区块只要拥有独立状态、局部交互、复杂样式、可命名职责或复用预期，就应优先考虑拆成视图单元，而不是揉进父视图。
- 组件拆分要让 owner 更清楚：父视图编排数据、路由动作和跨区块协作；子视图管理自己的展示状态、局部交互、内部结构和样式细节。
- CSS 也是可复用代码。重复出现的布局、间距、状态色、动画、响应式规则或 class 组合，应沉淀为组件、主题 token、CSS 变量、共享样式模块、工具类组合或应用约定的等价抽象。
- 页面私有样式跟随页面私有视图单元；跨页面复用样式跟随可复用组件或应用公共样式入口。不要把只服务单个页面的样式提前全局化。
- 不复制多份只改颜色、文案、图标或尺寸的 CSS 或模板。用结构化数据、变体字段、token、CSS 变量或 class 组合表达差异。
- 只为复用而抽取也要克制：没有状态、没有复用预期、没有复杂样式、不能被清楚命名的短小片段，可以留在父视图。

## 组件与图标

- 图标、按钮、菜单、弹窗、表格和表单优先使用当前应用选定的设计系统和图标库。
- 帮助入口、说明入口和仅图标操作必须提供可访问名称（`aria-label` 或同义机制）；需要说明时使用组件库的 `Tooltip` 或 `Popover`。
- 移动端操作可以压缩为图标，但不能牺牲可点击面积和语义标签。
- 不要手写 SVG 或用文本伪装图标；新增图标前先查询现有图标库，确认没有合适图标再向用户说明取舍。

## 文本超长处理

文本可能超出容器宽度或显示行数时，必须同时满足：

1. **视觉限制**：使用平台/框架的截断工具（Tailwind `truncate` / `line-clamp-*` 或对应框架方案）限制显示。
2. **悬停提示**：外层包裹 `Tooltip` / `Popover` 或同义组件，鼠标悬停时显示完整文本。

| 场景          | 处理方式           | 说明                               |
| ------------- | ------------------ | ---------------------------------- |
| 列表项名称    | 单行截断 + Tooltip | 文件名、歌曲名等可能超长的单行文本 |
| 详情页标题    | 多行截断 + Tooltip | 允许显示 2-3 行，超出部分截断      |
| 用户输入内容  | 截断 + Tooltip     | 任何由用户输入、可能较长的文本     |
| 卡片/面板标题 | 根据容器宽度自适应 | 通常单行截断即可                   |

补充：

- 所有被截断的文本都必须能通过悬停/点击等方式查看完整内容。
- 同类文本采用相同的截断策略。
- 移动端需考虑触摸长按的替代方案。

## 应用补充

每个应用可以在自己的 `docs/` 中补充组件库、主题 token、平台限制和验收方式。应用补充只能约束当前 app，不覆盖根层通用 UI 原则。
