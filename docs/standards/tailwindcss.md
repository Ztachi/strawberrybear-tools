# Tailwind CSS 规范

## 适用范围

本规范适用于启用 Tailwind CSS 或兼容原子类方案的 UI 应用。它是**技术类别**规范，不要求每个应用都必须使用 Tailwind；具体应用是否启用 Tailwind，由应用自己的构建配置和文档声明。

未启用 Tailwind 的应用忽略本文。

## 使用原则

- 新增或大幅修改的 UI 优先使用原子 class 表达布局、间距、排版、圆角、阴影、响应式和常规状态。
- 不为新 UI 建立页面私有的自命名 class 样式系统；命名 class 只用于原子 class 难以表达的视觉、动画或组件库覆盖。
- Tailwind 不替代应用设计系统；颜色、字号、间距和状态语义优先服从应用主题 token 或组件库 token。
- 可增长的同构 UI 仍应由结构化数据驱动，不重复模板或 JSX 堆叠 Tailwind class。

## 复用与组合

- 重复出现的长 class 或 className 组合，不应在多个视图单元里复制。优先抽成可复用视图单元、变体配置、class 组合函数，或应用约定的样式组合入口。
- 当一组原子 class 同时表达结构、布局、状态和响应式时，优先让拥有该结构的视图单元封装它；调用方通过语义化 props、配置或数据字段选择变体。
- 状态样式应由状态字段或变体字段驱动，例如 `selected` / `disabled` / `loading` / `danger` / `compact`，不在模板里复制多份只改 class 的分支。
- 页面私有的 class 组合留在页面私有视图单元附近；跨页面复用的组合跟随公共组件或应用公共样式入口。不要因为 Tailwind 使用方便，就把同一段视觉规则散落到多个页面。

## 局部样式允许场景

- 复杂关键帧动画、伪元素、渐变背景、遮罩、滤镜组合等用 CSS 更清晰的样式。
- 第三方组件内部结构的窄范围覆盖。
- canvas、图表、编辑器、游戏画布、固定比例预览等需要稳定尺寸或特殊渲染的区域。
- 平台差异或安全区处理无法通过普通原子 class 清晰表达时。

## 响应式

- 响应式优先写在 class、className 或框架等价样式入口中，例如 `md:`、`lg:`、`max-[760px]:`，避免为了普通布局使用 JS 监听窗口尺寸。
- 固定比例视觉资产使用 `aspect-*`、`max-w-*`、`object-contain`、`mx-auto` 等约束，移动端必须保证主体完整可见。
- 固定底部操作必须考虑安全区和内容遮挡；如果操作在文档流中能自然解决遮挡，应优先选择文档流布局。
- 文字必须在移动端和桌面端都能换行、截断或收缩到可读状态，不允许遮挡主操作。

## 验收

- UI 改动至少检查桌面和移动断点，确认文字不溢出、主操作可见、图片和图表不偏移或遮挡内容。
- 改动后运行对应应用的 type-check、build 和 `git diff --check`；涉及根层公共样式规则时运行仓库 `pnpm ci:check`（如有）。
