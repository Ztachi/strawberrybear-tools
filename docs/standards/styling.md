# 样式规范

## 文本超长处理

当文本可能超出容器宽度或显示行数时，必须同时满足以下条件：

1. **视觉限制**：使用平台/框架的截断类工具限制显示（如 Tailwind CSS 的 `truncate` 单行截断或 `line-clamp-*` 多行截断）
2. **悬停提示**：外层包裹工具提示组件，鼠标悬停时显示完整文本

| 场景          | 处理方式           | 说明                               |
| ------------- | ------------------ | ---------------------------------- |
| 列表项名称    | 单行截断 + Tooltip | 文件名、歌曲名等可能超长的单行文本 |
| 详情页标题    | 多行截断 + Tooltip | 允许显示 2-3 行，超出部分截断      |
| 用户输入内容  | 截断 + Tooltip     | 任何由用户输入、可能较长的文本     |
| 卡片/面板标题 | 根据容器宽度自适应 | 通常单行截断即可                   |

- 所有被截断的文本都必须能通过悬停/点击等方式查看完整内容
- 同类文本采用相同的截断策略
- 移动端需考虑触摸长按的替代方案

## CSS 优先原则

能用 CSS 表达的布局、尺寸、滚动和响应式约束，不要用 JS 测量 DOM 后再回写状态。优先使用 `flex`、`grid`、`min-height`、`max-height`、`calc()`、`clamp()`、CSS 变量和原生 `overflow`，只有在业务状态或组件 API 无法表达真实布局关系时才引入 `ResizeObserver`、`getBoundingClientRect()`、`debounce` 等 JS 布局计算。

应用级滚动条属于主题基础设施，应集中写在全局样式入口，并通过 CSS 变量或主题 token 表达颜色、hover 和轨道状态。不要在单个组件里硬编码滚动条颜色；覆盖 UI 框架内部滚动容器前，先检查组件配置、语义 class 和内部 CSS 变量，只有没有配置入口时才使用限定范围的全局选择器。

## Tailwind CSS 使用原则

启用 Tailwind 或兼容原子类方案的应用遵循以下规则：

- 新增或大幅修改的 Vue UI 优先使用 Tailwind 原子 class 表达布局、间距、排版、圆角、阴影、响应式和常规状态。
- 不为新 UI 建立页面私有的自命名 class 样式系统；命名 class 只用于 Tailwind 难以表达的视觉或框架覆盖。
- Tailwind 不限制具体布局形态；每个项目应根据业务场景和设计语言选择合适的栅格、弹性布局、定位和响应式断点。

### Scoped CSS 允许场景

- 复杂关键帧动画、伪元素、渐变背景、遮罩、滤镜组合等可读性明显更好的样式。
- Vuetify、Ant Design Vue 等第三方组件内部结构的窄范围覆盖。
- canvas、证书预览、编辑器、游戏画布等需要稳定尺寸或特殊渲染的区域。

### 响应式

- 响应式优先写在模板 class 中，例如 `md:`、`max-[760px]:`、`lg:`，避免为了普通布局使用 JS 监听窗口尺寸。
- 固定比例视觉资产使用 `w-[min(...)]`、`max-w-*`、`mx-auto`、`object-contain` 等约束，移动端必须保证主体完整可见。
- 固定底部操作必须考虑安全区和内容遮挡；如果操作在文档流中能自然解决遮挡，应优先选择文档流布局。

### 验收

- UI 改动至少检查桌面和移动断点，确认文字不溢出、主操作可见、图片不偏移或遮挡内容。
- 改动后运行对应 app 的 `type-check`、`build` 和 `git diff --check`。

## 应用专属样式

具体组件库的主题 token、品牌色、滚动条样式和框架 API 覆盖规则由各 app 的 `docs/design/` 维护，不在根层重复定义。
